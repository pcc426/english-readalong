# ADR-0003: 引入邀请制账号体系，以登录鉴权取代防火墙 IP 白名单

**Status**: accepted（取代 ADR-0002 的"不做账号体系"决策；ADR-0002 保留为历史记录）

## 背景

V0.1 只服务自家孩子，ADR-0002 决定不做登录、靠防火墙 IP 白名单控制访问。V0.2 开放给少量受邀家庭后，这一前提不再成立：每家的自定义内容与练习记录必须彼此隔离，家长需要在各自的设备上登录，外出场景也要可用——IP 白名单做不到按人授权，更做不到吊销一个已经泄露的访问途径。

## 决策

- **邀请制账号**：家长用邮箱 + 密码登录，密码只存 bcrypt 哈希（`bcryptjs` 纯 JS 实现，免原生编译）。账号只能由管理员经管理入口创建；首个管理员由一次性 CLI 脚本 `scripts/create-admin.ts` 引导创建。公网没有任何自助注册入口——这一点靠"不存在这个接口"保证，而非靠配置。不做自助注册、不做邮件找回密码（无 SMTP 依赖）。
- **服务端会话**：SQLite `sessions` 表存服务端生成的随机不透明 id（256-bit），浏览器侧用 HttpOnly + SameSite=Lax + Secure 的 cookie 承载，有效期 30 天。**不使用签名 cookie/JWT**：单进程 + SQLite 的部署形态下，吊销能力（退出即删行、可随时作废任意会话）和"无需保管签名密钥"的简单性全面优于无状态方案。
- **登录限速**：同一邮箱连续失败 5 次锁定 15 分钟（进程内存态，重启清零可接受）。实现上按邮箱与来源 IP（`x-forwarded-for` 首段，缺失记 `unknown`）各记一份失败计数，任一维度达阈值即锁——同邮箱爆破与同 IP 撞库两种形态都覆盖。限速是挡在线爆破的第一道闸，挡不住分布式撞库；邀请制的小用户量下够用，V0.2 不引入验证码。
- **受保护 API 统一 401**：业务接口经统一守卫（`src/lib/auth`）取当前账号，未登录/会话失效一律返回 401 JSON。
- **防火墙 IP 白名单降级**为纵深防御的辅助手段，不再是主要访问控制。Secure cookie 恒开：生产经 Caddy 走 HTTPS（iPad 麦克风本就要求），本地 localhost 属安全上下文可正常携带；若未来出现无 TLS 的部署，登录会显式失效而不是静默降级为明文密码传输。

## 后果

- 多家庭的内容私有与练习记录归属有了挂靠点（`accounts.id` 作为 owner），标准内容仍然全员可见。
- 既有 `practice_attempts.owner` 为 NULL 的历史记录需一次性迁移到管理员账号名下（V0.2 归属票处理）。
- ADR-0002 中"未来若向更多孩子开放，需要账号体系、付费额度与合规审查"的预判开始兑现；其"不做登录是有意偏差"的声明自本 ADR 起失效。未成年人个人信息合规审查仍是开放事项，随部署阶段处理。
