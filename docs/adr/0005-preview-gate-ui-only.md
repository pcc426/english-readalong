# 0005：预览门禁只做 UI 收敛，不加服务端强制

日期：2026-10-30
状态：Accepted

## 背景

V0.3 在「校对 → 定稿」之间插入预览环节（见 GLOSSARY「预览」）：末句确认后按钮变为【去预览】，定稿发布动作只允许从预览页发起。

直接发布的入口现有三个，都打同一个 `POST /api/drafts/[id]/publish`：

1. 校对页末句位置
2. `/custom/[id]` 草稿详情页
3. 管理员标准内容制作页（StandardAdminClient）

要做到「未预览不能发布」的服务端强制，需要给 `content_drafts` 加预览标记列（或新增状态）、publish 路由加状态校验、DB schema 补迁移，并处理 unpublish 回退后标记重置。

## 决策

不加数据库标记、不加服务端门禁。把上述三处入口的【定稿发布】统一改为【去预览】，所有发布动作在 UI 上只从预览页发生。publish API 维持「本人 + proofreading 状态即可定稿」。

## 理由

- 本应用是邀请制家庭应用（ADR 0003），使用者都是被邀请的家长与管理员，没有匿名/外部用户，绕过自己的预览页没有利益驱动。
- 服务端强制的成本是一次 schema 迁移与三处状态语义维护，换来的只是防住「账号持有者用 curl 跳过自己页面」，风险收益不成立。
- 预览本身不改变数据（不录音、不评分、不写练习记录），跳过它不会造成数据污染，最坏后果仅是发布者自己少看一遍。

## 后果

- 未来若开放注册或出现非可信角色制作内容，需要重新评估并补服务端门禁；本决策不约束那时的设计。
- 三个入口的收敛要在同一批改动里完成，避免出现某个页面仍能一键发布、链路体验不一致。
