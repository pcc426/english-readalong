# 10: bugfix——校对页状态提示栏常驻，消除高度跳动

**What to build:** 用户反馈：校对页「已保存」提示显示/消失导致右栏高度频繁跳动，编辑时很烦。现状（勘察）：提示是内联派生变量 banner + 条件渲染（`{banner && <p>…}`），无占位无 min-height；保存态在 use-draft-save.ts 置 saved 后 1.5s（SAVED_HINT_MS）清除 key，整块卸载塌陷；底部导航用 mt-auto 随之上跳。

现状只有「保存中…/已保存 ✓/保存失败/标题保存中…/标题已保存 ✓」，**没有**「句子有修改请重新确认」这句文案——本票一并补上。

1. 提示区域改为**固定高度、始终渲染**的占位条（建议 min-h 与单行文案等高、py 不变、位置仍在当前句卡片上方/原 banner 位置），只切换文案与颜色，不再挂载/卸载。
2. 状态集合（互斥单条，优先级在现有基础上调整）：
   - `saving` 保存中…（slate，带忙碌感即可，不加 spinner 库）
   - `saved` 所有修改已保存（emerald）——**常驻**，不做 1.5s 消失；下一次编辑开始时被 saving 替换
   - `needs-reconfirm` **句子已修改，请重新确认**（amber）——当前句存在未落定修改或服务端把该句 proofread 打回 edited 时显示（即当前句 proofread !== "confirmed" 且有过编辑；句子被 PUT 保存返回 edited 后即进入此态，点【确认本句】成功后回 saved）
   - `error` 保存失败，请重试（red，现有重试路径不变）
   - 标题保存沿用 saving/saved/error 同一占位条
   - 初始空闲（页面刚加载、无任何修改）显示什么？建议淡色 `所有修改已保存`（句子本来就 confirmed 时成立）；实现时若语义别扭可用空字符串占位但**高度不塌**
3. 删除 SAVED_HINT_MS 定时清除逻辑（use-draft-save.ts:107-114 与 page.tsx:159 标题侧的同款 setTimeout）；hook 对外暴露的状态形状相应调整，调用方只渲染不计时。
4. 底部导航条位置在连续打字/自动保存期间保持不动（录屏或测量验证）。

**Blocked by:** None

**Status:** ready-for-agent

## 实现要点

- SentenceRow.tsx 是死代码，不用动
- 结构操作（插句/合并/删除）的错误提示目前也走 banner：保留进同一常驻条（error 态），成功不需要额外文案
- 教材原文错位提示是另一种常驻信息，不要混进保存状态条（保持现有位置或原样条件渲染，它不参与跳动问题）
- use-draft-save 唯一使用方是校对页，改 hook 形状影响面可控；注意它的单测要同步
