# V0.3.5 规格：卡片 holder 尺寸收紧 + 清理验收孤儿包

状态：本地验收 v0.3.4 后的两条反馈（2026-11-04）
范围：小迭代；1 是纯样式（holder 尺寸），2 是数据清理（删除验收测试残留的孤儿包）

## 1. 三个列表页的卡片 holder 加宽、压扁

用户反馈：教材首页与自定义列表的卡片一行 6 个太窄（`minmax(168px,1fr)` + `max-w-7xl`）；教材制作列表的卡片（`minmax(180px,1fr)` + `max-w-6xl`）宽度合适。且卡片整体太长（9:16 封面），希望压缩高度让一屏能看到完整一行。

决策：
- **三个列表页统一**（教材首页 `page.tsx`、自定义列表 `custom/page.tsx`、教材制作列表 `StandardDraftList.tsx`）：
  - 容器 `max-w-7xl` → `max-w-6xl`（与制作列表一致）
  - 网格 `minmax(168px,1fr)` → `minmax(180px,1fr)`
  - 封面纵横比 `aspect-[9/16]` → `aspect-[3/4]`（object-cover 居中裁切，内容保留）
  - 卡内竖向间距小幅收紧（mt-2 → 保持，不加高）
- 不涉及任何功能：所有徽标、标题、枚举串、进度条、按钮、删除全部保留
- 1024×768 验证一行完整可见

## 2. 清理「The dragon dance」重复卡中的孤儿包

诊断：`data/content/standard/008cf111-14ec-4315-9459-7935304660a0.json` 是 2026-11-02 v0.3.4 验收时在**临时库**上发布的测试草稿包；临时库删除后包文件残留在共享磁盘，真实库无对应草稿行 → UI 无法删除（草稿删除接口 404），且与随代码包 `u2-dragon-dance.json`（同名 The dragon dance）重复。

决策：
- 删除孤儿包文件（仅此一个；`f5fcec05` / `2f8e5173` / `8aca6e91` 都有对应 published 草稿，是真实数据，保留）
- 顺带清理无对应包/草稿的孤儿练习记录（unit_id `518aa05e`、`7e2fdd25`，共 9 行；不清理也不影响 UI，属卫生项）
- 随代码的 `u2-dragon-dance` 是仓库内容本体，不动
- 不加代码层防重复逻辑（正常流程：已发布内容 → 退回校对 → 删除，可用；本次孤儿源于验收环境的 DB/磁盘生命周期错位，属一次性事件）
