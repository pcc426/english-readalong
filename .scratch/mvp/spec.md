# Spec: 小学英语跟读 MVP（U2/U3）

## Problem Statement

家长的孩子在上海读小学五年级，英语用沪教版教材，需要做课文跟读练习。市面上的跟读产品要么与教材不同步，要么订阅收费、广告多、交互花哨。家长手头已有基于教材自制的示范视频（网友制作，U2/U3 各一段），但"看视频"无法变成"逐句跟读 + 发音反馈"的练习闭环，家长也无从知道孩子读得如何、进步与否。

## Solution

一个部署在家庭 VPS 上的网页应用。孩子在 iPad 浏览器打开，选择单元（沪教版五上 U2《The dragon dance》、U3《Parts of plants》），逐句完成"看示范片段 → 跟读录音 → 获得讯飞评分与三星反馈 → 自动进入下一句"的练习。每句记录最好成绩及达成时间；单元页展示全单元的星级分布（三星/两星/一星的百分比）和 1-2 句鼓励语，形成"把单元刷满三星"的激励闭环。访问控制靠防火墙 IP 白名单，无账号体系（ADR-0002）。

## User Stories

1. 作为孩子，我想在首页看到单元列表及各单元的星级完成度，以便知道今天练什么、练到了哪。
2. 作为孩子，我想进入单元后按顺序逐句练习，以便跟着课文节奏走完整篇。
3. 作为孩子，我想在每句开始时看到对应视频片段自动播放一遍示范（画面+发音），以便知道这句怎么读。
4. 作为孩子，我想在示范结束后点击录音按钮朗读这句，以便系统评测我的发音。
5. 作为孩子，我想读完立刻看到这句的 0-100 分数和 1-3 颗星，以便获得即时成就感。
6. 作为孩子，我想在出分后约 1-2 秒自动听到下一句示范，以便保持练习节奏不被打断。
7. 作为孩子，我想随时点"再练一次"重录当前句，以便冲击三星。
8. 作为孩子，我想在句卡上看到这句的最好成绩和达成时间，以便知道自己是否在进步。
9. 作为孩子，我想在单元页看到"三星 X% / 两星 Y% / 一星 Z%"的分布（四舍五入）和一句鼓励语，以便有刷满三星的目标感。
10. 作为孩子，录音太短或没声音时，我想得到"没听清，再读一次"的提示而不是报错，以便知道该重读。
11. 作为孩子，网络或评分服务偶发失败时，我想被告知可重试且练习进度不丢，以便练习不中断。
12. 作为孩子，iPad 竖屏界面要有大按钮、大字体，以便触屏操作不费劲。
13. 作为家长，我想让新素材以结构化内容包（教材原文句子 + 每句起止时间 + 视频引用）加入 app，以便添加单元无需改代码。
14. 作为家长，我想对自动切分生成的句子清单做一次性校对（改文本、微调时间边界），以便素材与教材原文和音频一致。
15. 作为家长，我想让录音在服务端自动从 Safari 的 AAC 格式转成讯飞要求的 16kHz 单声道 WAV，以便评测兼容（ADR-0001）。
16. 作为家长，我想让讯飞评测调用全部收在评测服务接口之后，以便将来更换评测引擎只改一处（ADR-0001）。
17. 作为家长，我想让讯飞密钥只存在于服务器环境变量，以便不进代码库、不暴露给浏览器端。
18. 作为家长，我想用 VPS 防火墙 IP 白名单控制访问而不做登录，以便家中即开即用（ADR-0002）。
19. 作为家长，我想让每次练习都完整落库（即使界面只展示最好成绩），以便将来做进步分析不用补数据。
20. 作为家长，我想看到评分调用的基本日志（成功/失败/耗时），以便排查偶发问题和观察额度消耗。
21. 作为家长，我想用简单脚本把 app 与素材部署/更新到 VPS，以便维护省事。

## Implementation Decisions

- **技术栈**：Next.js 全栈（App Router，TypeScript）+ SQLite；视频与录音文件存服务器本地磁盘。部署到家长自有 VPS，防火墙 IP 白名单代替认证（ADR-0002）；讯飞密钥走环境变量。
- **内容包（内容数据 seam）**：每个单元是一个结构化内容包：单元元信息（标题、教材课文出处）+ 句子列表。每个句子含：教材原文文本（权威来源，GLOSSARY）、素材视频中的起止时间（秒）、视频引用。内容包带 schema 校验，加载失败要报明确错误。MVP 内容：U2《The dragon dance》、U3《Parts of plants》，由一次性数据准备产生。
- **素材数据准备（一次性）**：教材原文给出权威句子清单；用本地 whisper 做已知文本对齐得到起止时间，与视频画面字幕交叉参考；产出的清单交家长校对后定稿。素材是网友自制视频，音频/字幕与教材原文冲突时以教材原文为准（GLOSSARY），冲突句在校对清单中标记，由家长决定取舍。
- **评测服务 seam（ScoringService 接口）**：窄接口——输入教材原文文本 + WAV 音频，输出 0-100 句子总分。两个实现：
  - 讯飞实现：讯飞 ISE read_sentence（WebSocket + HMAC 签名）；服务端先用 ffmpeg 把 Safari 录音（AAC/M4A）转为 16kHz/16bit 单声道 WAV 再提交（ADR-0001）；
  - 假实现：可编程返回分数，供测试注入。
  星级映射：≥90 三星、≥75 两星、其余一星；阈值放配置，不写死（补偿英式发音偏差，ADR-0001）。
- **数据模型**：练习记录表（句子、得分、星级、时间戳，每次练习一条）＋每句最好成绩（查询得出或物化，需保证与记录一致）。单元完成度分布由记录聚合。
- **API 契约（缝 2）**：
  - 获取单元列表：单元 + 各自星级分布 + 鼓励语；
  - 获取单元详情：句子列表 + 各句最好成绩与达成时间；
  - 提交练习：音频 → 得分、星级、是否刷新纪录；空录音/评分失败返回明确错误语义（可重试），不静默。
- **前端页面**：单元列表页；单元页（句子网格 + 完成度分布 + 鼓励语）；逐句练习页（视频 seek 到句子起点播放片段 → 录音 → 出分与星星 → 自动流转，可重练）。触屏优先、大控件。

## Testing Decisions

- **只测外部行为，不测实现细节**。没有既有先例（greenfield），本 spec 建立的测试即先例。
- **缝 1（ScoringService）**：领域链路（录音接收 → 转码 → 评分 → 星级 → 落库 → 查询）全部用假评测器注入测试，快速、确定性、不耗额度。真实现（讯飞适配器）配独立的**集成冒烟套件**：固定 WAV 样本 + 教材原文文本调真实 ISE，断言返回合法分数且落在预期区间；该套件需要网络/密钥/额度，不在日常测试循环运行，作为适配器 ticket 的验收标准执行（联调点），之后评分相关代码变更或怀疑讯飞侧漂移时手动重跑。纯函数部分（如签名参数生成）可用已知输入输出离线单测。
- **缝 2（HTTP API）**：星级映射边界（89/90/74/75）、最好成绩合并、星级分布四舍五入、鼓励语选择、错误路径（空录音、上游失败）均通过 API 层 + 临时 SQLite 覆盖。
- **内容包**：schema 校验测试（缺字段、坏 JSON、时间倒置要报错）。
- **UI 不做自动化**：真机 iPad Safari 手工验收（麦克风权限流程、录音、视频片段播放、自动流转节奏），作为部署验收清单。

## Out of Scope

- 账号体系、多用户、公网推广；届时需未成年人个人信息合规（ADR-0002 已记录）。
- 音素级发音诊断与逐词纠音。
- 整段朗读挑战模式。
- 练习历史曲线、进步报告等家长侧分析（数据本期已落库，界面后置）。
- "电子教材 → 视频 → 切分"的自动素材管线工具。
- U2/U3 以外单元的内容制作；微信小程序 / 原生 App。

## Further Notes

- 讯飞 ISE 个人实名认证后免费额度 500 次/天，覆盖家庭用量；超量约 0.006 元/次（调研详见 research/scoring-engines.md）。
- 讯飞评测不区分英美口音（美式基准），教材偏英式——靠星级阈值校准补偿，不追求分数与学校评测完全一致。
- 素材视频的字幕不可作为文本来源（GLOSSARY"字幕"条目）。
- whisper 对齐只需在本机或 VPS 跑一次；两个素材共约 10-15 句。
